**[C2] A01 was incomplete: Host was not tied to the target (fixed in #53).** A01's scope asked for absolute-target/Host consistency, but the PR only fixed the path. Routing matched the absolute URL's host while the direct path forwarded the client's `Host` unchanged, so `GET http://a/` with `Host: b.internal` was matched against `a`'s noProxy/forceProxy rules and served by the origin as `b.internal`. An absolute-form request without Host was forwarded without one. RFC 9112 §3.2.2 requires the proxy to replace Host with the target's authority. #53 now does that for direct HTTP and Upgrade. The loopback script reproduces the bug before the fix (both decoy Host fields reached the origin) and asserts exactly one `Host:` afterwards. Requests forwarded to an upstream proxy are unchanged; that proxy applies the same rule.

**[C3] Server-first bytes were more urgent than their place inside A08 suggested (filed as #55, fixed on `fix/connect-server-first`).** After a successful upstream CONNECT, bytes the origin sent in the same read as the `2xx` were discarded with the handshake handler, and bytes arriving before the consumer's relay was installed hit the pipeline tail. Protocols where the server speaks first (SSH, SMTP, FTP, database handshakes) hung through an upstream proxy on every consumer: HTTP CONNECT, SOCKS5, proxied port tunnels and transparent. This is a user-visible correctness bug, not refactor debt, and #54's parser already retained the bytes, so the fix was small. A 2xx pauses upstream reads and leaves the handshake handler in place. Every consumer installs its relay through `CONNECTCoordinator.attachRelay`, which removes the handler afterwards, and the removal hands over the held bytes once and in order. `pm-sim server-first-connect` and `server-first-socks5`, plus a proxied-tunnel XCTest, time out without the change. **Still in A08:** bytes lost if the upstream closes *before* the relay attaches (NIO tears the pipeline down, so nothing downstream receives them), half-close, cancellation at every setup step, the two relay copies that truncate on close, and one shared splice.

**[C4] Parser details (fixed in #54's second commit).** Any 2xx is a tunnel (RFC 9110 §9.3.6), not only 200. The 64 KiB ceiling counted tunnel bytes coalesced with the 2xx, so a large greeting failed the handshake. It now bounds the response only, and an incomplete response at the ceiling fails instead of waiting. Whitespace before a chunk extension is accepted (RFC 9112 §7.1.1). `connection.upstream_invalid_response` was missing from `docs/events.md`.

**[C5] Don't make #48 wait on #46.** Today any same-UID process can already drive the helper's DNS/proxy operations (A03). An owner lease keyed on the console UID is therefore no weaker than the current trust boundary, and it fixes the failure users actually see: settings left pointing at a dead listener after a GUI crash. Put ownership behind an identity abstraction that #46 later strengthens (signed caller → lease owner), and ship the watchdog/restore without the signing-policy decision. Keep A06's persist-before-mutate, generation checks and restoring only settings still owned by that generation.

**[C6] Test determinism is now a real tax.** Four intermittent failures showed up in one afternoon, and they have different causes: `TunnelForwarderTests.testDirectTunnelForwardsBytes` (a real product cause: IP-literal connects wait on `getaddrinfo` through the contended global queue, #56), `DNSTCPListenerTests` (a real product race, #57), `TrailingDebouncerTests` (wall-clock assertions; the positive case was fixed in #58, the burst case needs a virtual clock), and `AppStateHarnessTests` restore (a missing async handle, #19). ## Decision

Keep the incremental approach and existing policy state machines, machine fakes, journal, and module boundaries. The assessment identifies useful extraction targets, but its work order understates immediate security fixes. Request-target serialization, upstream response parsing, helper authorization, and routing failure semantics must have explicit issues; they must not wait for the architectural extractions.

Do not make a wholesale orchestrator reducer extraction a prerequisite for shipping the daemon. First bound/offload blocking effects, share runtime composition, and define ownership/recovery. Then migrate execution and process boundaries in independently testable steps.

## Immediate change and validation

**A00 — CONNECT early-data process crash: merged in PR #52.** Both direct and upstream CONNECT paths removed the `.forwardBytes` decoder before `HTTPProxyHandler` and before installing raw relays. Removing the decoder forwards buffered raw bytes synchronously, which reached a typed HTTP unwrap.

- Before the fix, both new `pm-sim connect-early-direct` and `connect-early-upstream` scenarios exited 133 with `NIOAny.swift:208` and a type-mismatch fatal error. The fixture sends a CONNECT header and 19 bytes containing NUL and CRLF in the same write.
- Both paths now remove typed handlers and the encoder, install both relays, then remove the decoder last. No new module, dependency, or helper contract was needed.
- Both scenarios pass after the fix. They assert exact early + post-200 echo bytes and verify whether the fake upstream accepted a CONNECT, so a routing mistake cannot make the upstream regression pass through the direct path.
- The scenarios throw on failed assertions/timeouts, are included in `pm-sim all`, and run in ordinary CI as separate commands. Their failure does not depend on interpreting `notes`.
- Existing `websocket-upgrade` passes. Xcode `swift test`: **1,618 tests, 5 skipped, 0 failures**, about 105 seconds. The final scenario-only route assertion was subsequently rebuilt and both CONNECT scenarios rerun successfully.

This hotfix fixes client early-data handoff only. It does not claim to solve upstream server-first buffering, half-close, cancellation during setup, or all relay lifetime races. Those remain A08.

## Security findings and omitted work

### A01 — Preserve the wire request target; do not decode it into HTTP syntax

**Priority: P0. Reproduced; merged in PR #53, including target-derived Host replacement.** The fix preserves encoded origin-form targets for direct HTTP and Upgrade and rejects literal controls/spaces. Its 28 exact-wire cases and full test suite pass. The baseline finding follows.

This is more than a URL correctness issue. Both direct HTTP and direct Upgrade forwarding build `reqHead.uri` from `URL.path`. Percent-encoded spaces/CRLF become literal request-line/header syntax. NIO re-encoding cannot protect a URI that the application has already decoded into delimiters.

An isolated `pm-proxy --minimal --state-dir <temporary-directory> --port 0` and a raw loopback origin reproduced this. A request containing encoded CRLF in its path arrived at the origin as:

```text
GET /safe HTTP/1.1\r\nX-Injected: yes\r\nX-Tail: value HTTP/1.1\r\nHost: 127.0.0.1:<fixture-port>\r\n\r\n
```

An admitted proxy client controls the target. Impact is downstream header/request interpretation injection; severity depends on downstream processing and gateway exposure. The reproduction establishes header injection, not a demonstrated cross-user exploit or code execution.

**Issue scope:** separate validated destination identity from byte-preserving origin-form serialization in the existing request-target abstraction. Cover direct HTTP and Upgrade together. Preserve encoded delimiters, query ordering, duplicates, and an empty query delimiter; omit fragments according to the existing HTTP policy. Reject literal prohibited controls at the boundary. Check absolute-target/Host consistency while defining the serialization contract.

**Acceptance:** raw-origin tests for `%0D%0A`, `%20`, `%2F`, `%3F`, `%23`, `%25`, Unicode, empty path/query, and duplicate query keys. Assert exact emitted bytes and that one accepted request cannot create an extra request/header through URI decoding. Run the same corpus for direct HTTP and Upgrade.

Evidence: `HTTPProxyHandler.swift:643` and `:763`; `HTTPForwarding.swift:12`; SwiftNIO `HTTPEncoder.swift` writes `request.uri` directly. Extends the existing wire-target item in `refactor-notes-2026-09-09.md`.

### A02 — Harden the raw upstream CONNECT response parser

**Priority: P1. Parser hardening merged in PR #54; server-first relay handoff merged in #59.** The original crash path was source-confirmed, not reproduced against the old binary. New live malformed-response regressions verify graceful handshake failure, one structured rejection event, and pool-slot release after the fix. Remaining early-close/half-close and lifetime gaps are in A08. The baseline finding follows.

The upstream CONNECT handshake bypasses NIO's HTTP parser. `Int(Content-Length)` accepts negative values; the signed result participates in `totalConsumed` and is passed to `ByteBuffer.moveReaderIndex`. A sufficiently negative length produces an invalid index and traps. Chunk sizes also use signed integers and Swift string indices rather than byte offsets. Header length uses a character count while the destination index is a byte offset.

The attacker must control or impersonate a contacted upstream response; an ordinary downstream client cannot directly choose that response. Plain TCP upstream connections make an on-path attacker relevant. This is conditional process denial of service, not demonstrated memory corruption. The 64 KiB accumulated-buffer cap does not make malformed arithmetic safe.

**Issue scope:** a bounded byte-oriented parser, with distinct incomplete/invalid/complete results and explicit handshake states. Prefer existing codec support if it can preserve multi-round authentication correctly. Reject signed/overflowing/ambiguous lengths and invalid framing; handle 407 bodies safely. Successful CONNECT switches to tunnel bytes at the header boundary, with leftovers handed off exactly once. Avoid whole-buffer text conversion for binary tunnel data.

**Acceptance:** malformed, negative, oversized, duplicate/conflicting lengths; chunk extensions/trailers; UTF-8/binary data; every header split point; 407 then 200; 200 plus a server greeting in one read. Invalid input must fail the connection with an event, never trap or hang. Include a subprocess regression for the negative-length case.

Evidence: `CONNECTHandler.swift:311`, `:493`–`:562`; SwiftNIO `ByteBuffer-core.swift:1303`.

### A03 — Authorize the privileged caller, not just its Unix UID

**Priority: P1, required before claiming an installed helper is suitable for company use. Source-confirmed; already tracked as S04.** `HelperAdmission.refusal` admits any process with the active console UID. Such a process can request the helper's root-backed DNS, proxy, resolver, and relay operations. Version checks and argument validation constrain operations but do not authenticate the application.

This is a local privileged-operation delegation gap, not unrestricted root command execution. The socket is `root:staff` 0660, and other UIDs are normally rejected after their request is read.

**Issue scope:** define authorized signed app/daemon/administrative callers, update compatibility, and a distinct development policy. Bind mutations and later lease ownership to authenticated identity. Preserve per-operation validation and audit identity/action/result. Do not use a reusable same-UID-readable secret as the identity boundary.

**Acceptance:** same-UID unexpected process denied; intended signed callers accepted; stale helper/client versions, app update, logout, and fast-user-switch tests. Real signing checks belong on a controlled installation. Any wire-contract change needs the repository-required design agreement before implementation.

Evidence: `Sources/ConduitShared/HelperAdmission.swift:47`; `Sources/ConduitHelper/HelperDaemon.swift:66`, `:230`. Reuse S04 rather than filing a duplicate.

### A04 — Bound the entire helper transaction and isolate blocking work

**Priority: P1. Source-confirmed; overlaps S07/R04.** The helper has one serial accept loop. It sets a five-second receive timeout but reads a byte at a time before checking peer authorization. A staff-group peer can send each byte inside that timeout and monopolize the helper far longer than five seconds. The 1 MiB size ceiling is not an elapsed-time deadline. The client has blocking connect/write/read without a transaction timeout, so helper stalls can propagate to the GUI and recovery operations.

**Issue scope:** reject clearly unauthorized peers before draining their bodies; use a monotonic total deadline across request and response; handle partial I/O, EOF, disconnect, and cancellation; bound subprocess duration/output and concurrent work. Move waits off MainActor through the existing privilege seam. Preserve permitted logout teardown.

**Acceptance:** temporary unprivileged Unix sockets and fake operations cover drip-fed, partial, stalled, disconnected, and refused peers. Subsequent authorized work must proceed within the deadline. UI/control heartbeat remains responsive. A stuck transaction must not block lease expiry/restoration.

Evidence: `HelperDaemon.swift:97`–`:106`, `:192`–`:210`; `Sources/PlatformMac/HelperPrivilegeClient.swift`, `sendRequest`. The older plan's subprocess-status claim is partly stale: `HelperTool.swift:280` already checks command exit status; retain that behavior and address duration/output bounds.

### A05 — Preserve PAC transport and failure semantics

**Priority: P1. Source-confirmed policy gaps; production CFNetwork behavior needs a fixture.** `CFPACResolver.parseRoute` accepts `HTTPS host:port` as the same `.proxy` route as plain HTTP. `parseProxyList` also merges HTTP/HTTPS dictionaries into `PROXY`. The route/pool representation carries no TLS requirement, and the upstream bootstrap uses plain TCP. Accepting an explicitly secure proxy directive must not silently select plaintext transport. HTTPS PAC proxies have distinct semantics in the [PAC documentation](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Proxy_servers_and_tunneling/Proxy_Auto-Configuration_PAC_file#return_value_format).

Separately, `parseProxyList` returns `DIRECT` when every returned entry was filtered out as invalid/unsupported. `HTTPProxyHandler` treats PAC DIRECT as a bypass, independently of the post-failure strict-mode gate. An invalid route therefore becomes a new direct-routing permission. A deliberately authorized PAC can already request DIRECT; the gap here is inventing DIRECT from invalid data.

**Issue scope:** preserve transport kinds and distinguish explicit DIRECT, genuinely empty results, invalid results, unsupported directives, and evaluation failure. Refuse unsupported secure transports until implemented; retain a valid prior policy or return an explicit failure according to the documented policy. Preserve the current configured-host/port credential allowlist.

**Acceptance:** exercise the actual CFNetwork adapter as well as the string parser; record whether an HTTPS directive survives as HTTPS on supported macOS. No plain credential/request bytes may be emitted when TLS was required. Invalid/unsupported-only results must not synthesize DIRECT; explicit DIRECT follows its defined precedence. Cover mixed ordered HTTP/HTTPS/SOCKS/DIRECT chains.

Evidence: `Sources/ProxyPAC/CFPACEvaluator.swift:258`, `:291`, `:479`; `HTTPProxyHandler.swift:192`–`:204`; `ConnectionPool.swift:707`. Credential counterevidence: `Sources/ProxyAuth/AuthenticatorFactory.swift:47` already denies unconfigured/disabled authentication endpoints.

### A06 — Recover system settings after owner death with authenticated leases

**Priority: P1; design alongside A03/A04.** The GUI owns the active runtime, while the privileged helper has no lease/watchdog transaction tied to that owner. A process crash can leave DNS/proxy settings pointing at dead listeners. A daemon restart improves availability but does not itself make restoration correct.

**Issue scope:** helper-owned, durable records of previous and applied values, bound to authenticated owner/session/generation. Persist before mutation. Renew only for the active owner; expire independently of a blocked helper request or GUI task. Restore only settings still owned by that generation, so another app/admin/user's later change is not overwritten. Define crash-loop handling, reboot, helper restart, logout, and graceful release.

**Acceptance:** fakes test crash before/after each journal/apply/renew/restore step, interrupted restore, stale renewals, PID reuse, competing owners, setting changed externally, and repeated recovery. A controlled machine then verifies abnormal process death. Define availability restoration versus any future mandatory-proxy policy explicitly; removing proxy settings is not a security kill switch.

No helper implementation or installation is included in this patch. The versioned protocol/migration decision remains required before implementing the lease.

## Corrections to the supplied assessment

- **The CONNECT crash is real, but not every byte sent before the 200 necessarily reaches the same race.** The regression demonstrates a concrete coalesced-header/early-payload trigger on both paths. That is enough to establish the defect.
- **HTTP framing is not an unconditional security guarantee.** NIO's codecs are useful controls; application URI rewriting and the independent raw upstream parser bypass their protection.
- **“Every DNS cache miss discloses every name to three providers” is too broad.** Intercepts, configured internal names, supported query types, cache hits, and internal DNS answers affect reachability. The multi-provider fallback remains a privacy and amplification concern. See `LocalDNSForwarder.swift:519`–`:585`, `:647`–`:717`.
- **“Bounded” needs an aggregate-resource qualification.** Spooling uses per-body caps but its replay writes chunks without awaiting downstream writes, so the file can be queued in memory. Transparent listener initialization has no shared HTTP/SOCKS admission gate. See `HTTPRequestBody.swift:113` and `TransparentTCPProxy.swift:57`.
- **A timeout exists on helper reads, but it is not a transaction deadline.** The meaningful issue is slow-drip monopolization plus untimed client/process waits, rather than the complete absence of any helper timeout.
- **Not all planned hardening is missing.** Configured-endpoint credential authority, bounded PAC fetches, observable-target redaction, and shared HTTP/SOCKS admission already exist. Carry them through the refactor instead of reopening completed S01–S09 work wholesale.
- **Performance is under-measured, not entirely unmeasured.** `pm-sim --perf-baseline` already reports resource usage, and `scripts/perf-gate.sh` exists. The gap is representative release baselines, regression thresholds, and sustained-growth measurement.
- **“Simulation is impossible” is too strong.** Existing injected dependencies and NIO embedded channels support focused deterministic tests. The missing piece is systematic control over transport completion, clocks, and randomness across runtime flows.
- **TLS to upstreams is not yet a cheap, defined change.** It needs a preserved transport kind, hostname/trust policy, handshake timeout, authentication binding, downgrade refusal, and a supported implementation/dependency decision. HTTP/2 and MASQUE can wait for actual product requirements.
- **An import discipline and a process boundary are different guarantees.** Preserve the kernel's platform separation, but make forbidden imports/dependencies executable checks; absence of explicit framework links alone should not be asserted to make every forbidden Swift import fail.

This review did not independently recalculate historical commit/LOC counts, count every bootstrap/Date call, audit every settings binding, or exhaustively test Keychain/signing, PAC resource exhaustion, DNS packet correlation, or every parser. Those limits do not weaken the reproduced defects, but the report is not a clean bill of health for the unreviewed surfaces.
