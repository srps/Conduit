## Architecture and boundaries

RuntimeActor is a package global actor in ProxyKernel's abstractions. It supplies isolation; each host owns its resources explicitly. Orchestrator, lifecycle, recovery, lanes, reconciler, workflow/store, service core and command coordination share it. UI/AppKit and client presentation stay MainActor, NIO stays on its event loops, and blocking effects use the injected PlatformWork or bounded diagnostic writers.

[One capture flight](../Sources/ConduitRuntime/RuntimeCaptureFlight.swift) serves all collection kinds. The host freezes a value snapshot, revision and exact total in one owner turn. Pure row projection runs off the owner; the result commits there. Page waits and stream pulls share transport registration/cleanup. A first page waiting for its capture resumes through the ordinary cursor-R path, explicitly current, stale, expired or not captured. Age starts at capture, and shutdown wakes waiters immediately and rejects late results. There is one projection path, with no configuration mode, snapshot registry or new wire type. The [contract](design-runtime-host-contract.md) and [reviewed plan](experiments/runtime-actor-activation/capture-plan-review.md) document the shape.

Diagnostic writers retain the root session through one private destination-guard wrapper. Queued physical writes therefore keep authority until they end or the process exits. No new lease protocol, queue or budget is introduced. This implements decision 0017 rather than changing its policy.

## Resource captions and limits

The selected 8 MiB is retained encoded rows, with the existing staging charge for one capture of up to 4 MiB. It is not app RAM. The complete 10,000-row list accounts for 3,006,968 encoded bytes across 47 pages; two retained row sets account for 6,013,936 bytes. Optimized XCTest process samples are separate from production-profile samples; neither is installed-app RSS.

The [object-custody assessment](experiments/runtime-actor-activation/capture-object-custody.md) explains the additional lifetime of one frozen whole snapshot. Taking it adds no whole-array copy, but it can retain older storage after later mutations. A small-kind capture can retain an unselected larger connection collection, so the 10,000-row display cap is no whole-value RAM bound. Immutable fixtures do not witness this divergence. Three [standalone kernel copy-on-write observations](experiments/runtime-actor-activation/kernel-cow/README.md) measure the actual value type at 1,000 and 10,000 rows; they are not the host flight, real churn, app RAM or a memory bound. Shared strings are retained rather than duplicated.
