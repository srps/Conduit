## Corrections that materially change implementation

### PAC policy: #49, #50, #39, #34

`CFPACEvaluator.swift` combines `kCFProxyTypeHTTP` and `kCFProxyTypeHTTPS` into `PROXY`, and its string parser maps HTTPS to `.proxy`. The native meaning and emitted results still need a supported-macOS fixture; source inspection alone does not prove which directive produces which native dictionary. An unsupported secure transport must never silently become a plaintext connection. Preserve chain order and allow only fallbacks explicitly permitted by the chosen policy; dropping a secure entry must not invent a new fallback.

The adapter also synthesizes DIRECT whenever every entry was discarded. Its “safe-by-default” comment is incorrect for a policy-enforcing proxy. Simply throwing or returning `[]` is insufficient: `PACRoutingEngine.routeChainFuture` converts failures, missing evaluators and overload into empty routes, while `HTTPProxyHandler` can then use configured upstreams or a cached direct-reachability result. Introduce a result that retains the policy outcome through to the routing decision. Define empty and mixed-invalid behavior explicitly, including strict mode, force-proxy precedence and last-known-good policy lifetime. Old policy must not be silently retained across a changed PAC URL.

For #39 the internal case is currently `.alreadyRunning`, and the public method returns Void; the issue's `.alreadyInFlight` spelling is stale. The behavioral defect is real. A shared Task is preferable to an independently growing continuation collection. Waiting callers must observe failure as well as success, and one caller cancelling should not accidentally cancel work required by all others. Recheck configuration after joining an older generation.

For #34, execution time is not evidence that a PAC is host-only. PAC logic receives the URL and can vary by scheme, port, path or query. The current cache preserves those distinctions. Adding `isResolvable` can also introduce another lookup rather than remove one. Resolve once and reuse the result inside a PAC only if its owner can preserve the script's semantics. Longer TTLs need explicit network/policy invalidation and a documented staleness tradeoff.

### Recovery and responsiveness: #17, #18, #47, #48, #79

The daemon genuinely lacks LaunchRecovery and the three restoration calls. However, #17's assertion that restart necessarily overwrites the old prior value is too strong: `PlatformStateJournal.recordPrior` is first-write-wins for existing records. Add an exact fake-machine reproducer for the stranded-state sequence; the missing recovery itself is sufficient justification without asserting unconditional overwrite.

#47's original body should be replaced with its remaining work, preserving links to #65 and #72. Source confirms bounded helper I/O, bounded subprocess work, client transaction deadlines, and dedicated PlatformWork queues for selected paths. An async method can still perform synchronous blocking writes. Moving those writes requires operation serialization in SystemProxyManager and DNSManager, start/stop generation checks, ordering guarantees for configuration changes and a bounded termination drain. Do not just wrap individual calls in detached tasks.

#79 should share the operation coordinator developed for #47, rather than introduce another coordinator around the same managers. Keep #17 as a focused recovery fix first. Add the network-monitor seam independently if useful. #83 has already fixed the daemon credential-store seam. The absence of strict expected-failure tests is a checklist gap, not evidence that the hosts have identical behavior.

#18 and #48 require one coherent ownership design. A daemon as the sole client-side writer is compatible with the helper owning privileged leases, but not with two independent authoritative journals for the same settings. A modification-time reload plus a lock around only the final write is insufficient: any multiprocess alternative needs a locked read-modify-write transaction. Prefer avoiding that complexity.

For #48, persistence must succeed before mutation. Expiry must have its own scheduling and operation budget rather than sit behind the serial client request loop. Compare current settings with the generation's applied values before restoring. Cover helper restart, stale renewal, external changes, sleep/wake and partial restoration. Authentication and IPC compatibility design from #46 are production gates; pure lease-state tests can start sooner. Controlled installation remains separate from automated development on the serving machine.

### Boundaries and lifetime: #31, #32, #76, #78, #80–#82

#31 should distinguish failure-memory lifetime from synchronization lifetime. `GSSInitiatorGate.swift` documents a process-wide lock preventing concurrent entry into an unsafe system SSO plugin. Making one gate per runtime would remove that guarantee. Injectability for tests is useful while production shares the serialization primitive. Resetting a global retry memo when one runtime stops would interfere with another runtime and with draining connections.

#81 is an isolation and diagnostics issue, but its PID folders already protect processes reported as live; the issue does not establish that every startup deletes active peers' files. Make cleanup ownership explicit instead of relying only on PID liveness. `SpooledHTTPRequestBody.create` reaches directory creation through the singleton, and cleanup synchronously removes files: keep these filesystem operations off NIO loops. Preserve a spool service until its active requests drain. Use a private session directory, secure permissions and bounded storage; moving sensitive bodies into persistent state needs deliberate cleanup. Cleanup failure should emit an event, not retroactively turn a completed response into a failure.

#32 and #76 are one cohesive target-boundary change, optionally delivered as dependent PRs. #78's proposed HelperSubprocess move conflicts with their testable-core objective. Moreover, `HelperTransactionBudget` currently lives beside HelperSubprocess and derives the client budget from its constants; split shared budgets from the implementation without forcing PlatformMac to import helper execution code. Keep HelperLineIO accessible to both ends. There is no demonstrated benefit to duplicating ProxyControlBridge's mappings into consumers solely because its file is small. Moving declarations/access levels should preserve the wire payload and version behavior; semantic IPC changes need their own compatibility plan.

#80 is not a pure file move: `ProxyAuth/AuthenticatorFactory.swift` throws `CredentialManagerError.missingCredentials`. Separate neutral credential-unavailable semantics from Keychain storage failures while preserving `CredentialFailureClassifying` and the no-retry behavior for missing stored credentials. Keep payload compatibility fixtures; the move must not force users to re-enter credentials.

#82 correctly lists five call sites. `RuntimeEnvironment.init` also consults the home directory for exportDefaultFile, even in isolated instances. Make that policy explicit. Moving only userDefault to PlatformMac would pressure headless tools to add an unwanted dependency; use a small entry-point facility or explicit construction instead.
