# Refactor observations from the security fixes

These are concrete follow-ups encountered while implementing S01–S06 and reconciling the dev-mode documentation in PR #25. They do not expand the current patch. The security/remediation plan remains the implementation queue; entries below identify architectural work or narrower reliability issues to carry into that pass.

| Observation and evidence | Suggested follow-up and acceptance check |
| --- | --- |
| Privacy policy is duplicated in `ProxyKernel/Support/SensitiveValueSanitizer.swift` and `ConduitShared/ControlDiagnostics.swift`. Header and token rules already differ, and S06 must keep URL rules aligned explicitly. | Design a small Foundation-only shared privacy contract without making the kernel depend on control DTOs. Preserve diagnostics-specific topology filtering. Run one corpus against every sink and export path. |
| `HTTPProxyHandler.swift` combines body spooling, route decisions, response formatting, CONNECT, upgrades, and relay lifetime. Observation strings are formatted beside wire values throughout that file. | Extract existing responsibilities behind typed request/observation boundaries. Keep wire URIs out of observation DTOs by construction; test success, rejection, cancellation, and upgrades through the same contract. |
| `ActiveConnectionInfo.destination` remains mutable, and synthesized Codable decoding bypasses its sanitizing initializer. Similar decoding applies to `RuntimeEvent`. New live records are sanitized; arbitrary historical records are a separate ingestion boundary. | Decide whether observation DTOs are trusted transport values or invariant-enforcing types. If they enforce privacy, validate mutation/decoding too, retain JSON compatibility, and add legacy snapshot ingestion tests. |
| Direct HTTP/upgrade forwarding rebuilds the URI with `URL.path` and `URL.query` (`HTTPProxyHandler.handleDirectHTTP` / `handleUpgradeRequest`). The decoded `path` accessor can change percent-encoded path semantics. S06 preserves this existing forwarding code and tests query preservation. | Separate wire-target preservation from URL interpretation. Verify `%2F`, `%3F`, `%23`, duplicate query keys, and empty query delimiters against an origin that records exact bytes before changing behavior. |
| `AddressFamilyAwareResolver.initiateAAAAQuery` suppresses every IPv6 answer without a routable IPv6 interface, including the loopback literal. The S05 IPv6 fixture could bind `::1` but its direct SOCKS dial failed on this Mac; proxied IPv6 succeeded. | Handle literal addresses separately from global DNS-family availability. Reproduce loopback/ULA/global cases with injectable availability, without changing unrelated routing policy. |
| `pm-dns` signal sources are local variables in a task that finishes after startup, unlike `pm-tunnel.retainedSources`. Live DNS startup regressions needed their bounded kill fallback after SIGTERM. | Give standalone runtime hosts explicit ownership of signal sources and shutdown tasks. Verify TERM/INT closes listeners and exits within a deadline, without relying on process kill. |
| `AppState` directly constructs `NotificationManager` and `NetworkMonitor`, calls `requestAuthorization()`/`start()` during initialization, and posts notifications during lifecycle actions. `DevLaunch.makeAppState` and `AppStateHarness.launch()` cannot substitute them. | Add notification and network-path protocols with fakes injected in both compositions. Assert that dev/harness initialization makes no real notification authorization or path-monitor calls, and that lifecycle notifications and injected path events remain testable. Include daemon parity where applicable. Until then, document dev mode as partial isolation. |
| `RecordingLogSink` uses an unbounded array despite the general bounded-observability rule. The new simulation limits its fixture inputs, but long-running harnesses can retain every message. | Add a configurable recording cap and visible dropped-entry count; preserve deterministic test snapshots. Track production writer queues under existing R03 separately. |
| Threat-model and architecture prose describes some already-shipped work as planned (control sockets, snapshots, audit) and contains differing claims about credential types. | Refresh documentation from module boundaries and executable tests during the refactor pass. Distinguish enforced guarantees, partial migrations, and future work. |
