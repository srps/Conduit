# Conduit (app)

The SwiftUI/AppKit app and its client-side `AppState`. Views present bounded control snapshots and pages through `RuntimePresentationAdapter`; Settings values are local drafts until the private editor verifies their save.

- Runtime commands and observations cross `RuntimeClient` and `PrivateEditorClient`. `AppState` must not regain an orchestrator, runtime manager, reconciler, recovery observer or direct state-file writer. Runtime policy belongs in `ConduitRuntime` and its actual-host tests; retain app tests for composition, draft/receipt authority, presentation and AppKit termination.
- `AppComposition` supplies every runtime effect explicitly through `RuntimeHostEffects`, plus the app's helper installation, credential enrollment, login item, PAC preview and updater collaborators. Add a seam and fake for any new machine effect, and supply it in production, `DevLaunch.makeAppState` and `AppStateHarness.launch()`. Runtime fakes live in `Sources/PlatformMac/PlatformFakes.swift`. A dev instance must never reach installed-helper or login-Keychain operations. Notification authorization remains a separate app seam; network-path and wake observers belong to the host's effects.
- `AppState` takes a prepared `StateRootSession` and has no other construction path, so no writer exists without the state root's lease (decisions 0017 and 0028). `ConduitMain` prepares it through `PreparedAppLaunch` before SwiftUI builds the app, and a busy or refused root exits there. A harness or dev composition takes its session through `StateRootBootstrap` before it seeds. Do not add an init that takes a raw `RuntimeEnvironment`.
- Prefer extending an existing strategy or manager over another mode flag or `if` branch in `AppState` or a view.
- `App/DevLaunch.swift` builds the debug-only fake composition, selected by `--dev` or the exact `io.github.srps.Conduit.dev` bundle identity. `bundle-app.sh --dev` creates the distinct ad-hoc `Conduit Dev.app`; dev requests refuse helper/Kerberos worker modes before composition. Notification authorization, network-path and wake observation still use real OS adapters; automatic bundle selection does not fake them. Its windows are presented from AppKit on purpose: a `Window` scene with `defaultLaunchBehavior(.presented)` never came up for an instance launched from a terminal or `open -n`, `SceneBuilder` takes only `if #available` conditionals, and a `MenuBarExtra` label wider than its glyph is dropped beside a notch. The comments there say what was tried.
